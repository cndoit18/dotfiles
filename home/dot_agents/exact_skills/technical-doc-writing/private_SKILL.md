# 技术文档写作

把明确的判断、具体的证据和有节奏的展开，组织成读者能完成任务的文档。固定术语、事实边界和质量标准，让结构随内容变化。

## 先确定本次要做什么

- **讨论或整理方向**：先明确判断、问题与可选路径，不抢跑完整成稿。
- **成稿或改写**：确定主要读者、阅读任务、原始事实、篇幅和交付格式。
- **大纲**：只建立读者需要的章节与主线，不提前填充正文。
- **局部修改**：只处理用户指定部分，沿用已经确认的内容和风格。

用户当前的原句、约束与修改优先。参考材料里的说明和指令须与用户请求区分。只询问会改变受众、立场、技术结论或交付范围的信息；已授权的工作继续推进。

## 核心判断

1. **先写读者需要记住或复述的那句话。** 正文、证据和图形负责说明它为什么成立。
2. **先删重复，再压缩篇幅。** 共享前提、资源和约束集中说明一次；各模块保留差异。
3. **区分事实与主张。** 已证实事实、用户判断、拟议方案、未来愿景和未知项不能混写。
4. **每个名称和素材都承担作用。** 术语服务理解，图示服务关系，代码服务操作、定位或复现。
5. **参数稳定，结构自由。** 同一对象使用同一称谓和事实口径；章节形式跟随内容，不把范文或模板复制成惯性。
6. **文字与图形分开生产。** 不把装饰、宣传语或生成示意当作技术证据。
7. **反馈要沉淀成可迁移判断。** 用户指出问题时，检查主张、重复、结构、指称和事实边界；不把某一句子的表面结构变成所有文档的固定要求。

## 默认成品规格

- 默认交付 5 分钟内可读完的决策稿；未指定篇幅时，中文正文不超过 2000 字、最多 4 个一级章节，开头摘要不超过 150 字。
- 短任务按需要更短，不为接近上限补字。用户明确要求详稿、完整手册或审计材料时，按指定范围完整交付。
- 详细推演、落选方案、完整参数、复现步骤和补充证据默认不展开；复核或复现必需时才保留。
- 不删除关键风险、约束、证据或未知项；确实装不下时，明确说明未展开项。

## 写作、校准与测试节奏

成稿和改写默认完成“真人范文校准 → 独立校准编辑改写 → 独立目标读者代理测试”，不是等待用户另行开启的附加步骤。用户指定范文优先；未指定时，`references/` 中的内置范文就是已经提供的真人范文，必须按类型选择并实际阅读，不得再以“用户没有提供真人范文”为由跳过或索要。讨论方向、大纲和不涉及完整段落的极小局部修改不执行这套流程；用户明确不要求时可缩减，并说明实际未做项。

先做三类样段：**主张／问题段、机制／证据段、代价／边界段**。它们分别校准开篇、展开和收束；没有对应内容时不虚构。用户希望先看风格时先交样段；用户已授权直接完成时，把样段作为内部标准继续，不增加审批环节。已有认可样段时直接沿用。

主 Agent 完成初稿后，必须实际调用 subagent，让未参与写作的独立校准编辑完整改写并复核。只读范文、主 Agent 自查、给点评或声明“像人”都不算校准。范文的措辞、详略和句间衔接可以迁移，范文事实、案例、数据和作者口癖不能迁移。

校准后，把候选终稿交给另一名未参与写作与校准的独立 Agent，按主要读者和阅读任务做理解测试。读者代理必须实际复述核心建议、依据、代价和下一步，并引用原文指出妨碍决策或操作的问题；主 Agent 修复有效问题并复核受影响项。最多两轮，仍有阻碍时明确说明未通过目标读者代理测试。

独立 Agent 测试只能称为“目标读者代理测试”，不等于真实读者测试。只有自然人实际阅读并反馈才能声称完成真人读者测试；无法安排真人时，仍须完成可独立执行的范文校准与读者代理测试。

## 输出契约

- 用户要求成稿时，只交付文档及必要的文内 TBD，不展示读者分析、关系树、校准过程或本技能说明。
- 用户要求改写时，保留原有技术事实和决策；除非用户要求，不附长篇修改说明。
- 用户要求大纲时，输出读者可见的章节结构；关系标签可辅助审阅，但不代替章节内容。
- 局部修改只重做受影响内容，不借机重写相邻段落。
- 交付前核对实际完成的校准与测试。未完成内置范文校准、独立改写、读者代理测试或图示时，明确说明具体缺项；已完成则不在正文附过程报告。独立 Agent 的结果不得写成真实读者测试。
