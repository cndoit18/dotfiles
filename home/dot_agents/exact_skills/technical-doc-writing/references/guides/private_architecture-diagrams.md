# 架构图绘制与视觉验收

架构图用空间布局回答具体评审问题。默认交付**可编辑图源 + 已渲染图片**；只有 D2、Mermaid、LikeC4 或 SVG 源码而无图片，图示未完成。

## 1. 固定读图任务

画图前写一句内部读图任务，再只保留回答它所需的对象和关系。

- **系统边界与外部依赖**：用系统上下文图，不展开内部类、函数或文件。
- **可运行单元、存储与调用关系**：用容器／组件图；“容器”不等于 Docker。
- **请求顺序、分支与跨角色协作**：改用时序图或动态视图，不把架构图堆成流程图。
- **主机、网络区域与部署单元**：用部署图，不与逻辑组件混层。
- 核心图优先约 5～9 个节点；更多对象按读者任务拆成“总览 + 局部”，不靠缩小字号塞进一页。

先列内部事实表：`节点（名称、职责、边界）`、`边（起点、终点、动作／协议、同步／异步）`；所有节点、边须回指事实表，未知项标 TBD，不为对称美观补关系。

## 2. 用布局表达架构

查看 [版式样例](../../assets/architecture-style-example.png) 及其 [SVG 源文件](../../assets/architecture-style-example.svg)，只校准阅读方向、间距、层级、连线和视觉克制；**不得复制其中的系统、关系或结论到当前文档**。

1. **主链路一条主轴**：调用链默认从左到右，分层架构默认从上到下；主链路节点同行／列，分支置上或下，避免“蛇形”阅读。
2. **网格对齐**：统一节点尺寸、行列间距和端口，同级节点等宽等高；先定网格再写 SVG，不逐节点试坐标。
3. **边界有语义**：系统边界用浅底细线大容器和明确标题，外部角色与第三方系统置于边界外；不用多个彩色小框冒充分层。
4. **连线正交**：优先水平、垂直和直角折线，不用斜线；线不穿过节点、节点标题、边界标题或其他边标签，主链路尽量不交叉。
5. **箭头只表达一种方向**：一条边标一个动作或协议；双向交互拆成两条有标签的边，不用含义不明的双箭头。
6. **同步与异步不只靠颜色**：同步用实线，消息发布／消费用虚线并配短图例；确有第二种关系类型时才增加线型。
7. **标签短而具体**：节点用“名称 + 必要职责／技术”，边用“调用”“写入”“发布 OrderCreated”等动词短语；长解释移到图后正文。

## 3. 视觉规格

以最终插入文档后的尺寸验收，不只看编辑器放大视图。

- 白底或极浅灰底；标题 28～32 px，节点标题 18～22 px，辅助文字与边标签不小于 14 px；缩放至文档实际宽度仍清楚。
- 普通技术文档优先 1400～1800 px 宽的横向画布；PNG 以 2 倍像素导出，SVG 保留矢量版。
- 主色表示应用服务，另一低饱和色表示存储／消息，灰色表示外部对象；颜色通常不超过 3 类，线型与文字独立承载含义。
- 禁用渐变、立体效果、重阴影、装饰插画、无意义图标和彩虹配色；不用 logo 代替组件名称。
- 节点文字最多两行并留内边距；边标签带白底或置于空白区，线不穿字。
- SVG 按 `boundary`、`edges`、`nodes` 分组，提供 `title`、`desc`，文本保持为文本，不栅格化进图源。转换器对 `marker` 支持不一，节点图层可能遮住箭头；实际 PNG 缺箭头时改用显式三角形或调整图层／端点，不以源码存在 `marker-end` 代替检查。

## 4. 选择现有渲染路径，不隐式安装工具

### D2：单页架构图默认路径

用 D2 表达已核实的节点、容器和关系，不把布局试凑成事实。复制 [D2 样式类](../../assets/d2-architecture-style.d2) 中的 `service`、`store`、`external`、`direct`、`event` 定义，按实际语义建模；样式文件不含任何当前系统。

先确认 `d2 version` 和 `d2 layout`。TALA 自 v0.9.0 起内置于 D2，旧版能力可能不同。CLI 不在 PATH 时用 `D2_BIN` 指向已安装二进制，不让脚本隐式安装。

```sh
bash <skill-root>/scripts/render_d2.sh --layout elk <output-dir>/architecture.d2 <output-dir>/architecture
D2_BIN=/path/to/d2 bash <skill-root>/scripts/render_d2.sh --layout tala <output-dir>/architecture.d2 <output-dir>/architecture-tala
```

脚本先 `d2 validate`，再生成同名 SVG、PNG 并输出结构化结果，默认 TALA。长调用链、依赖图或 TALA 重排不稳时比较 ELK；首版过宽、交叉、字小或分组失真时，以**同一份 D2 源文件**渲染两种布局，按实际图片选择。不得改事实迎合布局，也不预设某引擎对所有图最优。

除节点和边外，D2 模型默认补齐评审语义：`shape: text` 与 `near: top-center` 作标题，`near: top-right` 作实线／虚线图例，`near: bottom-center` 作读图结论；外部对象标签注明“外部角色／外部依赖”。异步分界优先写入边标签，如“异步边界｜发布 OrderCreated”，不加悬浮、归属不明的装饰标签。图例或注释恶化布局时，缩短或移至图旁正文，不牺牲主链路。

TALA 有随机性，小改动可能整体重排；复现时固定 `--tala-seeds`。先用 D2 内置字体渲染并检查中文，不默认叠加多个大型 CJK 字体；自定义字体和放大导出可能触发 `retained font bytes exceed limit 67108864`，应先回退内置字体而非反复重试。

### LikeC4：多视图或需要持续维护的架构

适合同一模型生成上下文、容器、组件、动态和部署视图。先确认环境已有 CLI 及版本；下载、安装或升级须先获用户同意，不让 `npx`、`pnpm dlx` 隐式下载。

```sh
<existing-runner> likec4 validate --json --no-layout --file <model-file> <project-dir>
<existing-runner> likec4 export png -o <output-dir> <project-dir>
```

PNG 导出可能依赖 Playwright，缺失时说明且不自动安装。用户接受可交互 HTML 时可用 `likec4 build --output-single-file`，但不能冒充已交付的 PNG。

### Mermaid：小型调用链、流程和时序图

Mermaid 易维护，但自动布局未必满足架构图阅读方向。必须检查实际渲染图；若主轴弯折、分组错位或标签碰撞，简化视图或改用 D2／LikeC4／SVG，不堆不可维护的 `linkStyle` 补丁。

使用已存在且获准的 CLI：

```sh
mmdc -i architecture.mmd -o architecture.svg -t neutral -b white
mmdc -i architecture.mmd -o architecture.png -t neutral -b white -s 2
```

`mmdc --version` 失败先诊断；包装器的 `npx -y @mermaid-js/mermaid-cli` 会下载依赖，不能据此认定本地已安装。无安装许可时改用可维护 SVG 或标“待渲染”。

### 可维护 SVG：单张静态图或自动布局不达标时

按第 2～3 节网格生成 SVG，用环境已有浏览器或图像转换工具渲染 PNG。先确认工具支持 SVG，保存实际命令与退出码；不要假定各平台都有 `sips`、浏览器或转换器。不用 base64 图片代替可编辑源文件。

## 5. 渲染检查与回修

源码可解析不等于图可读。先生成最小完整版本，确认 PNG 实际生成，再打开图片检查，不得止于图源。

在最终显示尺寸逐项检查：

- [ ] 第一眼可辨起点、主链路和图要表达的结论。
- [ ] 所有已知节点、边、方向和协议均与事实表一致，无新增或漏画。
- [ ] 无文字截断、节点重叠、线条穿字、箭头被遮挡、边界误包含或画布边缘裁切。
- [ ] 同步／异步、内部／外部、当前／规划状态可区分，且不只靠颜色。
- [ ] 标签在实际尺寸可读，未靠缩小字号解决拥挤。
- [ ] PNG 非空且尺寸正确，SVG／图源可编辑，Markdown 引用实际存在的图片。

任一项失败，优先删次要节点、拆图或调网格，至少完成一次“修订 → 再渲染 → 复查”；未修复不交付，不能只报告“代码已生成”。

随后将**实际图片（不提供图源）**和读图任务交给未参与绘图的独立读者代理，不提供事实表或标准答案，让其复述起点、主链路、关键边界、同步／异步关系及无法辨认之处。主 Agent 对照原事实表核对，修复漏读、误读后再测。无法打开图片或安排独立代理时，分别标明“未完成视觉检查”或“未完成图示读者代理测试”，不得声称图已验收。

## 6. 交付

- 默认交付 `architecture.png`（插入文档）、`architecture.svg`（矢量版本）和实际可编辑图源；D2 保留 `.d2`，LikeC4 项目可另含模型文件。
- Markdown 以相对路径插入 PNG，图题说明图回答的问题；图源作相邻链接，不用正文复述整图。
- 渲染失败仍保留可编辑模型，显著标“图未渲染／未完成视觉检查”；源码、占位符或自报成功不算成品图。
