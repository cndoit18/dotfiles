# 文档原型

原型是起点，不是必须填满的模板。按读者任务选择最少但足够的结构。

| 需要讲清什么 | 推荐主线 | 常见问题 |
| --- | --- | --- |
| 技术方案 / 架构设计 | 建议与问题 → 方案与机制 → 依据与代价 → 落地与验证 | 用代码结构代替现实目标；只写收益不写代价 |
| 机制说明 | 界定对象与范围 → 具体场景 → 主链路或组件 → 异常与边界 | 以实现名词开场；无场景；把正常流程写成全部情况 |
| 架构演进 / 复盘演进 | 原约束 → 旧方案问题 → 新方案机制 → 新旧对照 → 尚未解决的问题 | 把演进写成宣传；不区分已发生、正在推进和未来规划 |
| ADR / 短决策 | 背景与问题 → 候选方案 → 决策结果 → 后果与验证 | 为求完整虚构候选或理由；漏写负面后果 |
| 故障复盘 | 影响范围 → 处置时间线 → 诱因与根因 → 判断校正 → 整改与验证 | 根因止于组件名；初步判断写成最终结论；整改无状态 |
| 版本发布 / 变更摘要 | 发布宣告 → 主要特性 → 附加增强 → 重要修复 → 完整变更入口 | 变更压成同级清单；宣传语和未核实性能数字 |
| 教程 / 排障 | 读者当前状态 → 具体操作 → 预期结果 → 失败分支 | 套技术方案模板；缺操作前提和验证 |

## 按内容选择，不按范文类型硬套

同一项目可混用原型：主文档按读者任务选主线，局部机制说明只在该节使用机制原型。真人范文类型须与当前参照单元一致；短决策、机制说明、架构叙述、故障复盘和发布说明不能互相冒充。
