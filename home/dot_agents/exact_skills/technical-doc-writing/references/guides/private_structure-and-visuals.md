# 语篇结构与图示

## 先建关系，再写段落

把内容拆成短单元，每个单元只表达一个主张、证据、约束、示例或行动，再组织成层级大纲，并标明各单元与上下文的主导关系。

| 关系 | 用途 | 检查点 |
| --- | --- | --- |
| 背景（Background） | 补足理解核心内容所需的上下文 | 只写读者尚不知道的背景 |
| 详述（Elaboration） | 为概括补充同一对象的细节 | 不切换对象或层级 |
| 证据（Evidence） | 提高主张可信度 | 观点、假设不能冒充证据 |
| 解决（Solutionhood） | 连接问题与方案 | 方案必须回应问题和约束 |
| 因果（Cause／Result） | 解释原因、机制或结果 | 时间先后不等于因果 |
| 条件（Condition） | 说明成立前提 | 条件应可判断、可验证 |
| 对比（Contrast） | 呈现关键差异 | 所有对象使用同一组维度 |
| 让步（Concession） | 承认限制并说明主张为何仍成立 | 不隐藏代价、风险和边界 |
| 顺序（Sequence） | 组织步骤或事件 | 按时间或依赖排序 |
| 并列（Joint） | 组织同层级独立单元 | 不把并列项写成因果或主从 |
| 总结（Summary） | 压缩已经表达的核心内容 | 不重复整章，不引入新主张 |

- 核心内容是核，解释、证据和限制等支撑内容是卫星；并列步骤、选项不要强行分主次。
- 每个语篇跨度指定一种主导关系，内部可以嵌套；不要为“一段一个标签”拆碎自然表达。
- 无法接入关系结构的内容，应澄清、调整位置、拆分或删除；禁止只补连接词掩盖断点。
- 暂时隐藏卫星内容，仍能辨认“问题—主张—方案—行动”；恢复后关键证据和限制必须完整。
- 关系图默认是内部工作稿，不把 RST 标签直接当正式标题。

## 建立内容层级

- 默认按“总括结论 → 关键组成 → 实现细节”展开；层级由概念包摄关系决定，不为凑层级多设标题。
- 子节只能细化父节的对象和主张，不跨层加入实现细节，不无提示改变目标、范围或结论。
- 隐藏下一层时，上一层仍完整自洽；展开下一层只增加精度和依据，不改变阅读主线。
- 目标与问题只写现实角色、场景、约束、可观察变化和验收标准，不出现代码结构。
- 方案与机制用领域对象、责任、交互和因果关系说明，不以代码文件或类结构组织章节。
- 只有具体实现层才写代码、接口签名、依赖、框架和部署细节；每项选择回指一个目标或约束。
- 删除具体实现后，目标、理由和方案机制仍应完整；若删除代码就说不清目标，先补目标。

## 图示优先

能用图清晰表达的内容优先实际配图，不能用长段文字或短列表替代；适合同维度比较的内容用一张表。

| 文字承担的工作 | 优先表达 |
| --- | --- |
| 组件、角色或系统的连接、调用和数据流向 | 架构图、拓扑图或数据流图 |
| 多步骤、分支、依赖或跨角色协作 | 流程图或时序图 |
| 状态及触发条件 | 状态图 |
| 多对象同维度差异 | 对比表 |
| 真实数据趋势、分布或比例 | 数据图表 |
| 界面位置、操作路径或运行结果 | 真实截图或标注界面图 |

- 图放在其回答的问题旁。图前最多一句读图重点；图后只补图无法表达的依据、限制或结论，不逐句复述图。
- 图中对象、箭头、状态和界面名称与正文一致；删除装饰性插画、无意义箭头和重复节点。
- 图必须来自已知技术事实；未知关系标 TBD，不为画面完整编造组件、数据、流程或界面。
- 目标环境支持图片或画板时，实际生成并插入；只能交付图源时明确标“待渲染”，不把源码或占位符当作已完成图示。
- 不适合图示的纯结论、证据或限制不强行配图；表格不能替代本应使用的图。
- 一张核心图只回答一个主要问题；起点、阅读方向、分组和箭头含义可辨；颜色不能作为唯一信息编码。
- 每张核心图应由未参与绘图的目标读者复述对象、关系和结论；无法实测时标“未经读者验证”，不得声称通过领会检查。
- 架构图的具体建模、网格布局、渲染、视觉检查和独立读者代理测试，按 [架构图绘制与视觉验收](architecture-diagrams.md) 执行；不以“源码可解析”代替图片可读。
