# 语篇结构与图示

## 先建关系，再写段落

将内容拆成短单元，每单元仅表达一个主张、证据、约束、示例或行动，再组成层级大纲，标明各单元与上下文的主导关系。

| 关系 | 用途 | 检查点 |
| --- | --- | --- |
| 背景（Background） | 补足理解核心内容的上下文 | 只写读者未知的背景 |
| 详述（Elaboration） | 为概括补充同对象细节 | 不切换对象或层级 |
| 证据（Evidence） | 增强主张可信度 | 观点、假设不能冒充证据 |
| 解决（Solutionhood） | 连接问题与方案 | 方案须回应问题和约束 |
| 因果（Cause／Result） | 解释原因、机制或结果 | 时间先后不等于因果 |
| 条件（Condition） | 说明成立前提 | 条件应可判断、可验证 |
| 对比（Contrast） | 呈现关键差异 | 所有对象用同一组维度 |
| 让步（Concession） | 承认限制并说明主张为何仍成立 | 不隐藏代价、风险和边界 |
| 顺序（Sequence） | 组织步骤或事件 | 按时间或依赖排序 |
| 并列（Joint） | 组织同层级独立单元 | 不写成因果或主从 |
| 总结（Summary） | 压缩已表达的核心内容 | 不重复整章或新增主张 |

- 核心内容为核，解释、证据、限制等为卫星；并列步骤、选项不强行分主次。每个语篇跨度设一种主导关系，内部可嵌套，不为“一段一个标签”拆碎自然表达。
- 无法接入关系结构的内容须澄清、移位、拆分或删除，不得用连接词掩盖断点。隐藏卫星后仍能辨认“问题—主张—方案—行动”；恢复后关键证据和限制完整。
- 关系图默认是内部稿，RST 标签不直接作正式标题。

## 建立内容层级

- 默认按“总括结论 → 关键组成 → 实现细节”展开；层级取决于概念包摄，不凑标题。子节只细化父节对象和主张，不跨层加入实现细节，不无提示改变目标、范围或结论。
- 隐藏下层时上层仍完整自洽；展开只增加精度和依据，不改变主线。删除实现后，目标、理由和机制仍完整；若删代码就说不清目标，先补目标。
- 目标与问题仅写现实角色、场景、约束、可观察变化和验收标准，不写代码结构；方案与机制以领域对象、责任、交互和因果说明，不按代码文件或类结构组织章节。
- 只有具体实现层才写代码、接口签名、依赖、框架和部署细节；每项选择回指目标或约束。

## 图示优先

能用图清晰表达的内容优先实际配图，不用长段文字或短列表替代；同维度比较用一张表。

| 文字工作 | 优先表达 |
| --- | --- |
| 组件、角色或系统的连接、调用和数据流向 | 架构图、拓扑图或数据流图 |
| 多步骤、分支、依赖或跨角色协作 | 流程图或时序图 |
| 状态及触发条件 | 状态图 |
| 多对象同维度差异 | 对比表 |
| 真实数据趋势、分布或比例 | 数据图表 |
| 界面位置、操作路径或运行结果 | 真实截图或标注界面图 |

- 图置于所答问题旁；图前最多一句读图重点，图后只补图无法表达的依据、限制或结论，不逐句复述图。纯结论、证据或限制不适合图示时不强行配图；表格不替代本应使用的图。
- 图中对象、箭头、状态和界面名称与正文一致；删除装饰插画、无意义箭头和重复节点。图仅基于已知技术事实，未知关系标 TBD，不为画面完整编造组件、数据、流程或界面。
- 目标环境支持图片或画板时实际生成并插入；只能交付图源时标“待渲染”，源码或占位符不算完成图示。
- 每张核心图只回答一个主要问题，起点、阅读方向、分组和箭头含义可辨，颜色不作唯一信息编码。
- 未参与绘图的目标读者应复述每张核心图的对象、关系和结论；无法实测标“未经读者验证”，不得声称通过领会检查。
- 架构图建模、网格、渲染、视觉检查和独立读者代理测试按 [架构图绘制与视觉验收](architecture-diagrams.md) 执行；源码可解析不等于图片可读。
