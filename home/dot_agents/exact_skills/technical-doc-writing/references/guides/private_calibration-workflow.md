# 写作与真人范文校准工作流

## 1. 提取事实与主张

先明确主要读者、阅读任务、交付类型、篇幅和必须保留的原句。把材料分为已证实事实、用户判断、拟议方案、未来愿景和待确认信息。

## 2. 建立内容地图

每个主要章节记录：本节判断、支持证据或场景、语篇功能、与前后内容的关系、信息状态和需要的图示。按读者认知顺序组织，不按源材料标题机械切分。

## 3. 用真人范文做样段校准

范文用于校准措辞、详略和句间衔接，不提供技术事实。优先使用用户指定范文；用户未指定时，直接使用本 Skill 内置的真人范文，它们属于已经提供的样本，不再向用户索要，也不扫描无关个人文件。

用户未指定范文时，每次成稿或改写都先运行 `bash scripts/references.sh` 获取简要目录；可加关键词做 AND 过滤，如 `bash scripts/references.sh 故障 复盘`、`bash scripts/references.sh ADR`。脚本路径相对本 Skill 根目录解析，不假设调用者当前目录。没有完全同型的内置范文时，选择阅读任务和参照单元最接近的一篇，只迁移可迁移的表达特征，不得因此直接跳过校准。

1. 按交付类型、语言和读者选择 1 篇主范文，必要时才补 1 篇，不一次加载全部范文。
2. 按输出的 file 和 read_next 读取同类型的完整章节或段落组。中文写作优先中文样本；英文样本只学结构与论证，不迁移翻译腔。
3. 提取少量具体依据：如何起笔、如何展开机制、如何收束代价与边界，并保留对应的短原文摘录。
4. 先做三类样段校准：**主张／问题段、机制／证据段、代价／边界段**。它们分别校准开篇力度、信息密度和收束方式。当前文档没有某类内容时不虚构，改用实际存在的对应单元。
5. 用户希望先看风格时，先交样段；用户已授权直接完成时，把样段作为内部标准继续，不增加审批环节。已有认可样段时直接沿用，不重复提案。

## 4. 完成初稿并实际校准

主 Agent 先写内容完整的初稿。交付前必须使用 subagent 启动一名未参与写作的独立校准编辑。

向校准编辑提供：主要读者、阅读任务、用户原始需求、原文或原始资料、待校准稿、所选范文、对应原文摘录和样段校准依据。不得只给“自然一点”或文件路径。

校准编辑必须：

- 先读原始需求、资料和范文，再读初稿。
- 直接交付完整校准稿，逐项修正模板化开头、抽象名词、机械转折、均匀句式和空泛收束。
- 实际迁移范文的措辞、详略和句间衔接，不只点评、评分或声称“已校准”。
- 不把范文事实、案例、数据、结论或作者口癖带入当前稿。
- 不把仍需验证的边界写成已成立事实；同一待办或边界只保留一处，前置后不得原样重复。
- 同时给出“原始意图一致性：一致／部分一致／不一致／无法确认”，逐项核对核心目标、范围、关键事实、决策、约束和非目标。

主 Agent 逐项复核事实与边界。修改影响主线、关键结论或图表时，交同一校准编辑复核；即使只改表达，最终稿也要由同一编辑确认确实经过改写。

若最终稿仍明显使用与范文无关的模板，校准编辑继续给出修订稿，不只判“通过”。最多两轮实际校准；仍不满足时明确告知“未完成真人范文校准”。

子 Agent 不可用、调用失败或没有返回完整校准稿时，明确告知“未完成独立真人范文校准”，不得将主 Agent 自查描述为校准。校准记录和修订过程默认不进入成稿。

## 5. 做独立目标读者代理测试

校准编辑完成复核后，主 Agent 必须再启动一名未参与写作和校准的 subagent。只向它提供主要读者、阅读任务和候选终稿，不提供初稿、范文、创作意图说明或期望答案，避免把设计解释误当成文档本身已经表达清楚。

读者代理按真实阅读任务完成以下检查：

1. 用自己的话复述文档建议做什么、为什么、依据是什么、代价或未知项是什么、下一步是什么；没有对应内容的项标“不适用”，不得替文档补造。
2. 回答“仅凭这篇文档，我能否完成指定决策或操作”，结论只能为“能／有困难／不能”，并引用造成判断的具体原文。
3. 指出读者必须猜测的指称、跳过的推理、相互冲突的说法和缺失的必要信息；只报告会妨碍阅读任务的问题，不做文风偏好评分。
4. 不直接改稿，把问题与原文摘录返回主 Agent。

主 Agent 对照原始资料判断问题是否成立，修复后让同一读者代理复核受影响项；若主线、关键结论或阅读任务发生变化，则换一名新的独立读者代理重测。最多两轮。全部关键阅读项通过才可称“已完成目标读者代理测试”；两轮后仍有阻碍时明确说明未通过。

这只是目标读者代理测试，不是真实读者测试。用户明确要求真人测试时，必须取得自然人的实际阅读反馈才能标为完成；不能安排真人时列出该缺项，但不得以此跳过上述独立测试。测试记录默认不进入成稿。
