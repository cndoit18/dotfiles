# 写作与真人范文校准工作流

## 1. 提取事实与主张

明确主要读者、阅读任务、交付类型、篇幅和必留原句；将材料分为已证实事实、用户判断、拟议方案、未来愿景和待确认信息。

## 2. 建立内容地图

各主要章节记录判断、证据或场景、语篇功能、前后关系、信息状态和所需图示；按读者认知顺序组织，不照搬源材料标题。

## 3. 用真人范文做样段校准

范文只校准措辞、详略和句间衔接，不提供技术事实。用户指定范文优先；未指定时直接使用本 Skill 内置真人范文，不再索要，也不扫描无关个人文件。

未指定时，每次成稿或改写先运行 `bash scripts/references.sh` 获取简要目录；关键词按 AND 过滤，如 `bash scripts/references.sh 故障 复盘`、`bash scripts/references.sh ADR`。脚本路径相对本 Skill 根目录解析，不依赖调用者当前目录。无完全同型内置范文时，选阅读任务和参照单元最接近者，不得跳过校准。

1. 按交付类型、语言和读者选 1 篇主范文，必要时才补 1 篇，不一次加载全部范文。
2. 按输出的 file 和 read_next 读同类型完整章节或段落组；中文写作优先中文样本，英文样本只学结构与论证，不迁移翻译腔。
3. 提取少量具体依据：如何起笔、展开机制、收束代价与边界，并保留对应短原文摘录。
4. 先做**主张／问题段、机制／证据段、代价／边界段**三类样段，分别校准开篇力度、信息密度和收束方式；缺少某类内容时不虚构，改用实际对应单元。
5. 用户想先看风格就先交样段；已授权直接完成则作为内部标准继续，不增加审批。已有认可样段直接沿用，不重复提案。

## 4. 完成初稿并实际校准

主 Agent 先完成内容完整的初稿，交付前必须用 subagent 启动未参与写作的独立校准编辑。

提供主要读者、阅读任务、用户原始需求、原文或原始资料、待校准稿、所选范文及对应摘录、样段校准依据；不得只给“自然一点”或文件路径。

校准编辑必须：

- 先读原始需求、资料和范文，再读初稿。
- 直接交付完整校准稿，逐项修正模板化开头、抽象名词、机械转折、均匀句式和空泛收束。
- 实际迁移范文的措辞、详略和句间衔接，不只点评、评分或自称“已校准”。
- 不带入范文事实、案例、数据、结论或作者口癖。
- 待验证边界不得写成事实；同一待办或边界只留一处，前置后不得原样重复。
- 给出“原始意图一致性：一致／部分一致／不一致／无法确认”，逐项核对核心目标、范围、关键事实、决策、约束和非目标。

主 Agent 逐项复核事实与边界；改动主线、关键结论或图表时交同一编辑复核。即使只改表达，同一编辑也须确认最终稿确实经过改写。

最终稿仍明显套用与范文无关的模板时，编辑继续给出修订稿而非只判“通过”；最多两轮实际校准，仍不满足则明确告知“未完成真人范文校准”。

子 Agent 不可用、调用失败或未返回完整校准稿时，明确告知“未完成独立真人范文校准”，主 Agent 自查不算校准。校准记录和修订过程默认不进成稿。

## 5. 做独立目标读者代理测试

校准编辑复核后，主 Agent 必须另启一名未参与写作和校准的 subagent，只给主要读者、阅读任务和候选终稿；不给初稿、范文、创作意图说明或期望答案。

读者代理按真实阅读任务完成以下检查：

1. 用自己的话复述建议做什么、为什么、依据、代价或未知项、下一步；无对应内容标“不适用”，不得补造。
2. 回答“仅凭这篇文档，我能否完成指定决策或操作”，结论只能为“能／有困难／不能”，并引用造成判断的具体原文。
3. 指出需猜测的指称、跳过的推理、冲突说法和缺失的必要信息；只报妨碍阅读任务的问题，不做文风偏好评分。
4. 不直接改稿，将问题和原文摘录返回主 Agent。

主 Agent 对照原始资料判断问题是否成立，修复后由同一读者代理复核受影响项；主线、关键结论或阅读任务变化时，换新独立读者代理重测。最多两轮；全部关键阅读项通过才可称“已完成目标读者代理测试”，两轮后仍有阻碍须明确说明未通过。

目标读者代理测试不等于真实读者测试。用户要求真人测试时，只有自然人实际阅读并反馈才能标为完成；无法安排真人须列出缺项，但不得跳过上述独立测试。测试记录默认不进成稿。
