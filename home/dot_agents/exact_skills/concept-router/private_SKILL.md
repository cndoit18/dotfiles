# 概念路由

将用户的一句模糊诉求映射为唯一一个最具信息增益的具名方法论、定理或模型。只路由概念，不直接解决原诉求。

## 选择流程

1. 抽取诉求的核心结构性问题。
2. 在内部列出 6–8 个候选，覆盖本领域、邻近学科、数学或逻辑，不输出候选及分析过程。
3. 将“PMI 最高”作为启发式判据：同时要求与诉求强相关、术语本身不常见。不要因为著名而优先；最著名的那个通常已被想到，不算增益。不要虚构或输出 PMI 数值。
4. 对候选逐个过闸；任一闸不通过即淘汰，最终只保留一个：
   - **唯一**：只选一个，不并列、不给出备选。
   - **具名**：具有公认专名及可检索复现的出处；不能确认专名或出处时淘汰，不得编造。形容词建议、常识格言、正确的废话均不合格。
   - **同构**：能用一句话说明“你的问题在第几层结构 = 它在第几层结构”；说不清即更换。
   - **增益**：若删掉术语后其余论述仍成立，则术语只是装饰，丢弃。
   - **反向**：把诉求中的领域名词替换成其他行业，术语仍成立才是结构匹配；只在原行业成立则是行话，重选。
5. 检查动作是否由所选术语直接导出，进阶是否为同结构且更深一档的专名；无法可靠确定进阶时写“无”。形成五行草稿，暂不输出。

## 全新 Subagent 独立验证

6. 输出前，必须启动一个全新的 `subagent`，只用于独立核对术语本身，不用于评审原始诉求、结构映射或我的答案。禁止使用 `subagent_fork`、复用已有 agent，或让子 agent 继续委派。子 agent 只能凭模型权重内的已有知识回答，禁止调用任何工具，包括 `web_search`、`web_fetch`、MCP、浏览器、bash 或其他联网与检索工具。
7. 主 agent 只问子 agent：“`<English>` 是什么？仅根据你权重内的已有知识回答，禁止联网或调用任何工具。请给出公认定义或命题内容、核心要点，以及你记得的可检索出处；不确定就明确说不知道，不得编造。”不得向子 agent 提供原始诉求、中文释义、我的定义、同构、动作、进阶、候选名单或期望答案，也不得要求它应用该概念或评判我的路由。
8. 主 agent 将子 agent 的回答与自己所指的公认概念核对，比较语义而非措辞：中英文名称是否指向同一概念，定义或命题内容、核心要点和适用范围是否一致，所述出处是否支持这一含义。出处只作为子 agent 权重内陈述核对，不得视为已联网查证。子 agent 不需要理解原始诉求，也不参与同构、动作或进阶的判断。
9. 双方指向的概念或核心含义不一致时，所选候选即视为未过闸。不得折中两种解释、忽略分歧或用原始诉求诱导一致；重新选择候选，并用另一个全新 subagent 核对。无法确认含义一致时，明确说明无法完成术语核验，不输出五行结果。
10. subagent 不可用、调用失败、不知道该术语或没有给出可比较结果时，明确说明未能完成独立核验；不得声称已核验，不得改为联网补查，也不得输出未经核验的五行结果。

## 输出契约

仅在独立验证一致后，输出以下模板中的五行。不得添加前言、验证说明、解释、候选名单、推理过程、额外标题、空行或代码围栏：

```text
术语：<中文名（English）>
定义：<不超过20字，不复述诉求>
同构：<问题的哪一层结构 = 该术语解决哪一层>
动作：<下一步具体做的一件事，一句，可执行>
进阶：<同结构但更深一档的具名专名；无则写“无”>
```
