# 基于搜索的 Prompt 优化参考

本文件定义主流程的默认搜索取证协议，在必要输入确认与故障诊断后、实质改写前执行。搜索用于确认或推翻影响改写的外部假设，不替代其他优化方法或对照验证。

## 一、检索闸门

默认执行搜索。仅当以下两个条件同时成立时允许跳过：

1. 全部修改均可由原始 prompt、用户约束和已验证的本地上下文推出。
2. 修改不依赖模型／工具行为、时效性、外部实践或效果判断。

跳过时在主输出验证行记录“未搜索：修改均来自本地已确认信息”。不得以节省时间、用户未要求“最新资料”或已有通用经验为跳过理由。

## 二、定义决策问题

把待确认的改写决策转成一至三个可证伪问题，例如：

- 目标模型或工具的当前官方约束是否否定原 prompt 的假设？
- 原 prompt 的技巧是否有同模型、同任务的实测支持或失败证据？
- 同类任务是否已有可复用结构、示例或评测，能够修复当前执行偏差？

每个问题必须对应一项可能发生的修改；不能改变任何决策的问题不得用于检索。

## 三、按固定顺序检索

1. **官方资料**：检索目标模型或工具当前的 prompting guide、模型专属指导、迁移指南、发布说明和 API 约束。具体模型 ID 未确认时明确标注，不把同系列模型视为完全等价。
2. **可复现实测**：官方资料不能确定实际行为时，寻找同模型、同任务且方法可复现的对照实验或评测；记录模型、任务、输入和限制。
3. **社区经验**：需要实际用法、失败案例或争议信号时，按问题选择 GitHub、X、HN、Reddit、技术博客或论坛。无需机械覆盖所有平台；用户指定平台或需要判断社区共识时，必须尝试对应平台。
4. **控制证据新旧**：官方当前文档优先；社区实践默认优先近半年，并明确起止日期。旧资料只作背景。日期未知的官方当前文档可证明当前建议，但不能标为近半年发布；无日期社区材料不得作为近期证据。
5. **复核关键正文**：对驱动实质修改的来源使用可用的正文抓取方式复核。只有搜索摘要时标为“未复核正文”，不得扩写摘要中不存在的结论。
6. **处理检索失败**：平台不可访问、工具不可用或证据不足时，记录真正影响结论的限制，并继续其他适用的优化方法；不得编造来源、检索行为或“最新趋势”。
7. **达到决策阈值即停止**：已有足够证据回答检索问题，或继续检索不会改变改写时停止。除非用户要求系统调研，不追求穷尽平台、来源或技巧。

## 四、评价并使用证据

对真正影响修改的来源记录：链接、日期或当前状态、模型与任务、适用条件、证据类型、正文核验状态及对应修改。

证据类型区分为：**官方硬性约束、官方建议、可复现实测、经验观点**。来源权威性与实际效果证据不得混为一谈，社区热度不等于有效性。

按以下规则使用：

- 官方硬性约束必须遵守；官方通用建议与已确认的用户需求冲突时，不得盲抄，应说明并按根本需求调整。
- 社区经验与官方行为建议冲突时，优先寻找同模型、同任务的可复现实测；未解决的分歧保留为待验证假设，不静默折中。
- 每处实质修改都必须追溯到已确认问题、用户约束或证据。搜索结果是改写依据之一，不是要复制进 prompt 的模板。
- 对搜索驱动的模型行为修改，在主流程的对照验证中至少保留一个能区分旧假设与新建议的样例；未执行时明确标注。

## 五、对主输出契约的补充

搜索影响了实质修改，或用户要求解释依据时，补充简短的“依据与验证”：

1. 只列真正驱动修改的来源，附可点击链接、日期或当前状态、模型或任务、证据类型及正文核验状态，并说明各自影响了哪项修改。
2. 披露会改变结论可靠性的限制，包括关键正文未复核、模型版本不确定、平台不可达和 A/B 未执行；跳过搜索时说明原因。
3. 不输出完整搜索日志，不罗列未采用资料；只有用户要求系统调研或覆盖范围本身影响结论时，才说明平台覆盖与时间窗。
